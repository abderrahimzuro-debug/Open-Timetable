# خطة تحديث الواجهة (Qt في مكانها)

> قرارك: تحديث واجهة FET الرسومية في مكانها، التشغيل على **جهاز في المؤسسة**، بثلاثة أدوار:
> **مدير الجداول / أستاذ / طالب**. هذا المستند يحوّل القرار إلى مراحل قابلة للتنفيذ.

## المبدأ الحاكم

1. **لا نلمس المحرّك** (`src/engine`): كل ما يخص التوليد والقيود يبقى كما هو.
2. **التغيير طبقي**: مظهر مركزي ← هيكل النافذة ← إعادة بناء الشاشات واحدة واحدة.
   لا نعيد كتابة 337 ملفًا، ولا نكسر ما يعمل.
3. **كل تعديل يُصرَّف في CI** قبل الدمج (`job: our GUI from fet/`)، لأن بيئة العمل هنا لا
   تحتوي Qt — هذه هي شبكة الأمان.
4. **العربية أولًا**: RTL + خط عربي + ترجمة، لا "لاحقًا".

## المرحلة 1 — المظهر المركزي ✅ (منجَزة في هذه الجولة)

| ما أُضيف | الأثر |
| --- | --- |
| `src/interface/ui_theme.{h,cpp}` | نمط **Fusion** موحّد + لوحة ألوان عصرية + **QSS** (أزرار، حقول، جداول، تبويبات، قوائم، أشرطة تمرير) |
| خط عربي تلقائي | يختار أول خط متوفّر من: Cairo، Noto Sans Arabic، Noto Naskh Arabic، Segoe UI، Tahoma |
| مظهران جاهزان | `light` (الافتراضي) و`dark` — جاهزان لربطهما بخيار في الإعدادات |
| اللغة الافتراضية | `ar` (كانت `en_US`) + RTL يعالجه FET أصلًا عند اختيار العربية |
| ترجمة عربية | `scripts/fet-build-translations.sh ar` → `fet_ar.qm` بجانب التنفيذي |

سطر واحد فقط في `fet.cpp` يفعّل كل ذلك، فلا مخاطرة على بقية الشيفرة.

## المرحلة 2 — هيكل النافذة الرئيسية (الشريط الجانبي + لوحة البداية)

الشكل الحالي: شريط قوائم + عشرات الأزرار. المقترح:

```
┌────────────────────────────────────────────────────────────┐
│  Open-Timetable        [المؤسسة]           [حفظ] [توليد]   │  ← شريط علوي
├───────────┬────────────────────────────────────────────────┤
│ ▸ لوحة    │                                                │
│ ▸ البيانات│            محتوى الشاشة الحالية                 │
│ ▸ القيود  │                                                │
│ ▸ التوليد │                                                │
│ ▸ الجداول │                                                │
│ ▸ التقارير│                                                │
│ ▸ الإعدادات│                                               │
└───────────┴────────────────────────────────────────────────┘
```

- استبدال شريط القوائم بـ **QListWidget جانبي** (أيقونة + نص) داخل `FetMainForm`.
- **لوحة بداية**: بطاقات (عدد الأساتذة/المواد/الأفواج/الأنشطة) + أزرار سريعة + حالة آخر توليد.
- إبقاء القوائم القديمة في البداية كـ"وضع متقدّم" لتجنّب فقدان أي وظيفة.

## المرحلة 3 — توحيد شاشات البيانات

الشاشات الحالية (أساتذة، مواد، أفواج، قاعات…) متشابهة لكنها مكرّرة يدويًا.

- مكوّن واحد قابل لإعادة الاستخدام: جدول + بحث + إضافة/تعديل/حذف + استيراد لصق.
- نبدأ بالكيانات الخمسة الأكثر استخدامًا، ثم الباقي تدريجيًا.
- تحقّق فوري من الصحة: أسماء مكرّرة، حقول ناقصة، مراجع مستخدمة قبل الحذف.

| 8 | أدنى ساعات يومية — لكل الأقسام | `ConstraintStudentsMinHoursDaily` |

تفاصيل التنفيذ:
- الملف: `fet/src/interface/ui_constraints.{h,cpp}`.
- **لا تعديل على المحرّك**: نبني كائنات FET الأصلية ونضيفها بـ`addTimeConstraint`/
  `addSpaceConstraint` ثم `addUndoPoint` ⇒ القيود تظهر في «كل القيود الزمنية/المكانية»
  وتُحفظ في ملف `.fet` وتُصدَّر كأي قيد مضاف يدويًا.
- شبكة الأوقات تعمل في الوضع العادي ووضع **صباح/مساء** (`MORNINGS_AFTERNOONS`).
- «الوزن %» ظاهر لكل قالب (100 % = صارم، وأقل = يُسمح بالمساومة عليه).
- قائمة جانبية داخل النافذة تعرض **القيود الموجودة من نفس النوع** فورًا.
- مدخل من ثلاثة أماكن: الشريط الجانبي، قائمة **البيانات**، و**Ctrl+Shift+T**.

### القسم الثاني — الضروريات ⏳ (لم يبدأ)

الأنواع التي تحتاجها المؤسسة لكنها أقل تكرارًا، وتُبنى على نفس الأساس:

- عدم تزامن مادتين/أستاذين في وقت واحد (`Constraint*NotOverlapping`).
- قاعة مخصّصة لمادة/نشاط (`ConstraintSubjectPreferredRoom`, `ActivityPreferredRoom`).
- توزيع الحصص: حدّ أقصى للحصص المتتالية، وحصص في فترة محدّدة.
- فجوات الأفواج المتقدّمة، وقيود الأنشطة المتعدّدة (min days between activities).
- عرض القيود كبطاقات مفهومة بدل جدول تقني + بحث داخلها.
- «الوضع المتقدّم»: القائمة الكاملة كما هي الآن (لا تُحذف أبدًا).

## المرحلة 5 — لوحة التوليد

- مؤشّر تقدّم + الزمن المنقضي + حدّ زمني (إعداد افتراضي 120 ثانية بدل بلا حد).
- زر **إلغاء** وإيقاف عند أول جدول صالح.
- سجل مبسّط: "جارٍ التحسين… 3/7 قيود صعبة…".

## المرحلة 6 — عرض الجداول والطباعة

- عرض موحّد: اختيار (سنوات/أفواج، أساتذة، قاعات) + تصفية بحث.
- تصدير PDF/CSV/HTML، وطباعة عربية سليمة (خط مضمّن، رؤوس مكرّرة).

## المرحلة 7 — الأدوار الثلاثة (قرار معماري مطلوب)

هذه النقطة تحتاج حسمًا لأنك اخترت **برنامج سطح مكتب** + **ثلاثة أدوار** معًا:

| الخيار | الوصف | ملاحظات |
| --- | --- | --- |
| أ) تصدير فقط | المدير يولّد ويصدّر جداول HTML/PDF إلى مجلد مشترك على شبكة المؤسسة | أبسط، بلا خادم، بلا كلمات مرور (`fet-cl` ينتج HTML لكل أستاذ/فوج أصلًا) |
| ب) خادم محلي مدمج | نفس البرنامج يقدّم مجلد الجداول عبر HTTP داخل الشبكة المحلية (زر "تشغيل الخدمة") | المتصفح فقط للعرض، بلا تعديل بيانات؛ QTcpServer بسيط |
| ج) أدوار كاملة | حساب لكل أستاذ/طالب + تسجيل دخول + صلاحيات + قاعدة بيانات | يعني خادمًا حقيقيًا + تطويرًا كبيرًا (الأقرب لواجهة ويب) |

**القرار المتَّخذ: (أ).** وتم تنفيذه فعليًا في هذه الجولة:

- إجراء جديد في القائمة: **File ▸ Export ▸ «نشر الجداول إلى مجلد مشترك (شبكة المؤسسة)…»**.
- يولّد كل الجداول (أساتذة/سنوات/أفواج/فرق/قاعات/مواد) + XML + إحصاءات + سجل التعارضات
  داخل مجلد جديد مؤرّخ، وينسخ ملف البيانات الأصلي.
- يكتب **صفحة بداية عربية RTL** (`index.html`) ببطاقات منظّمة وروابط كل الجداول، و`README.txt`.
- يتذكّر مجلد النشر، ويفتحه بعد الانتهاء، ولا يكتب فوق أي نشر سابق.
- الدليل الكامل (مشاركة ويندوز/سامبا، الطباعة، القيود): `docs/PUBLISH.md`.

الخياران (ب) و(ج) يبقيان مؤجّلين؛ الترقية إليهما لاحقًا لا تكلّف شيئًا لأن النشر الحالي
ينتج نفس ملفات HTML التي سيقدّمها أي خادم عرض.

## إصلاح اللغات (منجَز) ✅

**العَرَض الذي بلّغ عنه المستخدم:** «اللغات الأخرى لا تعمل مهما ضغطت».

**الأسباب الحقيقية الثلاثة (تشخيص كامل للمسار):**

| # | السبب | الأثر |
| --- | --- | --- |
| 1 | خطوة بناء الترجمات **سقطت من وظيفة ويندوز** أثناء إعادة هيكلة سير العمل | الحزمة التي جُرّبت على ويندوز **كانت بلا أي ملف `.qm`** ⇒ FET يعود تلقائيًا إلى الإنجليزية |
| 2 | `fet-build-translations.sh` تُنشئ **العربية وحدها**، وسير العمل يستدعيها بـ`ar` | بقية الـ37 لغة غير موجودة أصلًا في الأثر |
| 3 | الشريط الجانبي ولوحة البداية **نصوصهما عربية مكتوبة مباشرة** (بلا `tr()` ولا `retranslate`) | تبقى عربية حتى لو تغيّرت لغة FET |

**ما أُصلح:**

- `scripts/fet-build-translations.sh --all` يستخرج **كل** اللغات من الأرشيف ويبنيها بـ`lrelease`.
- سير العمل: الوظيفتان (لينكس/ويندوز) تبنيان **كل** الترجمات، ثم:
  - فحص في اللينكس والويندوز: **يفشل البناء** إن كانت الحزمة تحوي أقل من 30 ملف `.qm`
    أو غاب `fet_ar.qm` ⇒ لا يمكن أن يتكرّر هذا العطل بصمت.
- `fet/src/interface/ui_i18n.h` جديد: `UiI18n::T("English", "العربية")` يختار النص
  حسب `FET_LANGUAGE` الحالية.
- `UiShell::retranslate()` و`UiDashboard::retranslate()` تُعيد بناء كل نصوص
  الشريط الجانبي ولوحة البداية، وتُستدعى من `setLanguage()` في FET ⇒ التبديل **فوري**.
- `TimetableGenerateForm::otApplyLanguage()` للوحة التوليد، و`UiPublish` رسائله
  ثنائية اللغة (الإنجليزية/العربية).
- `FetMainForm::languageChanged()` إشارة جديدة، واللغة تُحفظ **فورًا** في `QSettings`
  (`language`) لا عند الخروج فقط.
- الفحص الذاتي صار يتحقق من: اللغة الحالية، وجود ملف `.qm` الخاص بها، عدد اللغات
  المرفقة (≥30)، وأن نصوص واجهتنا تتبع اللغة.

**السياسة اللغوية:** نصوص FET الأصلية تتبع ملفات `.qm` (37 لغة). نصوصنا الجديدة
(الشريط الجانبي، لوحة البداية، لوحة التوليد، رسائل النشر) مُعرَّفة بالعربية
والإنجليزية؛ أي لغة أخرى تعرضها بالإنجليزية تلقائيًا (سلوك متوقّع ومعلن).

**التحقق:** اختيار الفرنسية/الإنجليزية من **Settings ▸ Language** يغيّر القوائم
والشريط الجانبي ولوحة البداية في نفس اللحظة، ويبقى بعد إعادة التشغيل.

## كيف ترى النتيجة؟

بعد نجاح CI يُرفَع أثر `open-timetable-gui-linux-x86_64` (يحتوي `fet` + `fet-cl` + ترجمة عربية).
على جهازك:

```bash
# لينكس
sudo apt install qtbase5-dev qtbase5-dev-tools qttools5-dev-tools build-essential
mkdir -p build/gui && cd build/gui && qmake ../../fet/fet.pro CONFIG+=release && make -j"$(nproc)"
cp ../../build/translations/fet_ar.qm .   # بجانب التنفيذي
./fet
```

على ويندوز: أثر البناء من سير العمل (أو بناء محلي بـ Qt 5.15/6.x + Qt Creator).
